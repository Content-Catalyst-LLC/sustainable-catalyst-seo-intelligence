# SC-SEO-02.1C · Search Console collection decision

**Decision for review:** use a small first-party read-only Google Search Console adapter in SC-SEO-02.2. Keep SiteOne for technical crawls and Studio for evidence and investigations. Continue to accept offline Google exports in the current release.

The review used [CrawlSEO source at 25e3c312](https://github.com/crawlseo/crawlseo/tree/25e3c312e122a4b42acf23b58c4de795b2cdf6a8) on November 20, 2026. The source is MIT licensed. The official API comparison used the [API reference](https://developers.google.com/webmaster-tools/v1/api_reference_index) and [usage limits](https://developers.google.com/webmaster-tools/limits).

| Criterion | A · Integrate CrawlSEO data capabilities | B · First-party Search Console reader |
| --- | --- | --- |
| API coverage | Existing site discovery, Search Analytics sync and URL Inspection client. The reviewed Google client does not expose Search Console sitemap inventory. CrawlSEO's crawler can discover sitemap XML separately. | Start with selected-property Sites, Search Analytics, sitemap list/get and indexed-version URL Inspection. Keep the existing Page Indexing export for aggregate coverage history. Search Analytics rows are performance evidence and can be incomplete. Sitemaps API inventory describes submitted sitemap files. Read actual XML separately for membership. |
| Indexing semantics | The boolean helper in [the pinned inspection client](https://github.com/crawlseo/crawlseo/blob/25e3c312e122a4b42acf23b58c4de795b2cdf6a8/lib/google/url-inspection-client.ts) maps two exclusion strings to true and errors to false. A separate helper returns the status string or null. Direct import would require reviewing call sites and using the raw response to preserve unknowns and provenance. | Preserve Google verdict, coverage, page fetch, indexing directives, last crawl and both canonicals separately. Treat quota or authorization failures as collection errors. This endpoint inspects the indexed version and provides no live test. |
| Auth and security | Auth.js Google login requests identity scopes and `webmasters.readonly`. OAuth token storage uses [AES-256-GCM](https://github.com/crawlseo/crawlseo/blob/25e3c312e122a4b42acf23b58c4de795b2cdf6a8/lib/google/token-store.ts) with support for migrating legacy plaintext. Integrating the service adds its app secret, database, identity model, worker and egress policy to the operational boundary. | Reuse Workspace identity and an approved server-side secret store. Restrict exact property and read-only scopes in the connector. Keep tokens out of URL params, receipts and logs. Log property-scoped request outcome and source digest. |
| Deployment and maintenance | [Compose](https://github.com/crawlseo/crawlseo/blob/25e3c312e122a4b42acf23b58c4de795b2cdf6a8/docker-compose.yml) defines a Next.js app, separate Node worker and PostgreSQL 16. Operators own image pinning, migration, backup, upgrades, job isolation and egress. Extracting only the Google code would still require adapting its user and token store contracts. | Add a bounded scheduled task to the existing application. The team owns Google endpoint changes, OAuth refresh, timeouts, pagination, deduplication and quota-aware retry. No new UI or database service is required if the approved Workspace store is available. |
| Memory and cost | A resident web app, worker and database require memory, disk, backup and maintenance capacity. Optional PageSpeed and commercial data features add resource or vendor considerations. | An on-demand worker can process bounded pages and exit, with storage limited to approved evidence. Expected lower idle overhead by architecture. Neither option was deployed or memory-benchmarked, so comparative RSS and infrastructure cost remain unmeasured. |

A lockfile-only `npm audit --package-lock-only --omit=dev --json` returned 48 affected dependency entries, including 6 critical and 24 high, in the registry report at review time. These entries include advisory propagation through the dependency graph and do not establish application exploitability. The result adds patching and verification work to adopting the full service. The audit installed no dependencies and used no account data.

Before enabling Option B, test the exact selected property and scope, quota backoff and secret handling in isolated staging. Google currently documents 2,000 URL Inspection requests per day per site, with separate project quotas. Inspect evidence-driven samples first. This change adds neither Google credential storage nor a live Google API client. [Google limits](https://developers.google.com/webmaster-tools/limits)
